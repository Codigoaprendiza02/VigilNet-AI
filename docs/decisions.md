# Design Decisions — VigilNet AI

This document logs design decisions, architectural assumptions, and data schemas for VigilNet AI.

## Database Collection Shapes (MongoDB)

We use MongoDB Atlas for dynamic, schema-less document storage. This matches the flexible nature of agent prompts, evasion briefs, and heterogeneous transaction payloads.

Below are the intended shapes of the collections:

### 1. `events`
Represents individual transactions (attacks generated by Red Team, or standard transactions used in testing/training).
```json
{
  "_id": "ObjectId",
  "event_id": "string",
  "round_id": "string",
  "persona": "string",            // "card_tester", "synthetic_identity", etc.
  "timestamp": "ISODate",
  "amount": "double",
  "merchant_category": "string",
  "merchant_id": "string",
  "account_id": "string",
  "is_synthetic_attack": "boolean",
  "payload": {                    // persona-specific variables
    "card_present": "boolean",
    "device_ip": "string",
    "location": "string",
    "sequence_order": "int"
  },
  "detection_result": {          // populated after scoring
    "score": "double",
    "is_flagged": "boolean",
    "detector_layer": "string"   // "tabular", "graph", "sequence", "text", "ensemble"
  }
}
```

### 2. `rounds`
Tracks round-level executions, metadata, and lifecycle progress.
```json
{
  "_id": "ObjectId",
  "round_id": "string",
  "status": "string",            // "running", "completed", "failed"
  "started_at": "ISODate",
  "completed_at": "ISODate",
  "personas_active": ["string"],
  "evasion_brief_ids": ["string"]
}
```

### 3. `personas`
Stores agent persona configuration details, state, and system prompts.
```json
{
  "_id": "ObjectId",
  "persona_id": "string",        // "card_tester", "structuring_smurf", etc.
  "name": "string",
  "description": "string",
  "system_instruction": "string",
  "current_evasion_directives": ["string"], // history of directives applied
  "created_at": "ISODate"
}
```

### 4. `evasion_briefs`
Created by the Miss-Analysis Agent (Gemini 2.5 Pro) based on Blue Team misses.
```json
{
  "_id": "ObjectId",
  "evasion_brief_id": "string",
  "round_id": "string",
  "target_persona": "string",
  "analysis_timestamp": "ISODate",
  "missed_patterns_summary": "string", // Natural language analysis of the false negatives
  "directives": ["string"]             // Actionable rules for the Red Team persona to bypass the detector
}
```

### 5. `metrics`
Stores aggregated performance metrics per round and persona.
```json
{
  "_id": "ObjectId",
  "round_id": "string",
  "persona": "string",
  "timestamp": "ISODate",
  "metrics": {
    "total_attacks": "int",
    "true_positives": "int",
    "false_negatives": "int",
    "recall": "double",
    "precision": "double",
    "false_positive_rate": "double",
    "f1_score": "double"
  }
}
```

---

## Architectural Assumptions & Decisions

1. **Gemini SDK**: We use the new official `google-genai` Python library. It relies on the environment variable `GEMINI_API_KEY` for authentication.
2. **Caching & Round Management**: Redis acts as the fast status tracker and message bus for the orchestrator, storing active round ID and streaming counts for the React dashboard.
3. **Async Operations**: Async is used wherever possible (using `motor` for MongoDB and `redis.asyncio` for Redis) to ensure high-throughput processing during large rounds.
